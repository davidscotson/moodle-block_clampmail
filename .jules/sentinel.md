## 2026-08-16 - IDOR and CSRF in Moodle Block Signature Management
**Vulnerability:** In `signature.php`, signature viewing, updating, and delete confirmation screens did not validate that the requested signature ID belonged to the logged-in user, allowing arbitrary users to load, modify, and hijack other users' signature records via simple form/parameter tampering. Additionally, the deletion confirmation URL was missing a session key parameter, leading to CSRF or validation failure.
**Learning:** Standard form processing with `$mform->get_data()` in Moodle is vulnerable to Insecure Direct Object Reference (IDOR) via tampered hidden fields unless explicit verification is performed to confirm that the submitted ID belongs to the current user's authorized records before invoking database operations like `$DB->update_record`.
**Prevention:** Always validate submitted hidden record IDs against a list of authorized IDs belonging to the active session user before executing updates or deletion confirmations.
