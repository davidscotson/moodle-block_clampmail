## 2026-01-07 - Insecure Direct Object References and Parameter Tampering in CLAMPMail
**Vulnerability:** Lack of user ownership and course context validation when querying and updating database records allowed IDOR and parameter tampering in `email.php`, `signature.php`, and `alternate.php`. Users could view or edit other users' email logs/drafts, hijack other users' signatures by tampering with the record `id` hidden field in forms, or delete alternate emails from other courses.
**Learning:** Standard Moodle forms using `$form->get_data()` or dynamic dispatching entry points do not automatically enforce record ownership or context containment when executing `$DB` operations. This is especially true for `update_record` calls where only the primary key is validated.
**Prevention:** Always verify that loaded database records belong to the active course context and to the current user (unless the user has administrative/impersonation capabilities). Before updating records from submitted form data, explicitly verify ownership of the record using `$DB->record_exists` or `MUST_EXIST` and overwrite sensitive fields like `courseid` using verified values from the active context.
