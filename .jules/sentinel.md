## 2026-07-31 - IDOR and Form Tampering in CLAMPMail Alternate Email Management
**Vulnerability:** Insecure Direct Object Reference (IDOR) via missing course-level security scoping and lack of unconditional record verification prior to updates. Specifically, `get_one($id)` fetched any alternate email record by global record ID without restricting it to the context of the course, and the `interact` method did not unconditionally load the original record from the database to ensure the course context was verified.
**Learning:** In Moodle, multi-tenant or course-scoped records must always validate security ownership at both the user level and the course context level. Relying on simple database ID queries without scoping by course/context can allow attackers to access or modify records in other courses.
**Prevention:** Always include context variables like `courseid` in search parameter arrays (`get_record`) and database write operations (`delete_records`). When handling incoming form data, always fetch the pristine existing database record using the verified context before executing updates to prevent form-tampering-based IDOR.
