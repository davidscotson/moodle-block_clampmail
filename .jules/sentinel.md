## 2025-05-18 - CSRF Protection on Course Configuration Reset
**Vulnerability:** The course configuration reset action in `config.php` could be triggered via a GET/POST request with `reset=1` without checking the Moodle session key (`sesskey`). An attacker could induce an authenticated instructor or administrator to visit a malicious link or embed a forged request image, resetting the block's course configuration to default settings without the user's intent.
**Learning:** While forms extending `moodleform` include automatic CSRF token protection upon submission via `$form->get_data()`, standalone action triggers or reset links embedded within forms as static HTML elements (like the reset link rendered by `classes/config_form.php`) bypass the form's internal CSRF protections unless explicitly supplied with `'sesskey' => sesskey()` and validated with `require_sesskey()` in the controller script.
**Prevention:** Always validate session keys via `require_sesskey()` for any state-changing actions performed outside standard `moodleform` validation, and ensure all generated action links append the session key token.
