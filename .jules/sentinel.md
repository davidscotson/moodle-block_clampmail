## 2026-08-09 - IDOR and CSRF Vulnerabilities in Email Logs and Drafts Management
**Vulnerability:** Insecure Direct Object Reference (IDOR) and Cross-Site Request Forgery (CSRF) issues allowed users to load, view details of, and delete email logs or drafts belonging to other courses or users. The `email.php` loaded drafts/logs without verifying user ownership or course context, while `emaillog.php` and `email::cleanup`/`email::delete_dialog` allowed deleting and viewing logs/drafts without proper course/user scoping and without a valid session key validation (`sesskey`) on deletion confirmation.
**Learning:** Performing database queries like `$DB->get_record` or `$DB->delete_records` using only a single record ID (`id`) is a common source of IDOR if the application does not explicitly scope the search criteria to the active user's identity and active course context. Additionally, state-changing redirection/confirmation actions must always include the Moodle session key to satisfy the security token checks.
**Prevention:** Always enforce strict context-aware scoping in database queries. Pass and validate both the current `$courseid` and `$userid` when retrieving, updating, or deleting sensitive records, and ensure Moodle's `sesskey()` parameter is present in confirmation links and validated on execution.
